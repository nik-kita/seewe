# L3 link cache (delete-on-write + TTL ceiling) & case-preserving display values

Refines [[009.plan]] with user direction.

## 1. Go L3: URL-keyed full-Response cache, invalidate on write

Deno Deploy Cache API facts (from the blog + api ref): persists indefinitely
(>=30 days), TTL via `Cache-Control`/`Expires`, `Cache.delete(request)` exists
(-> bool), exact-URL match, Deploy-only. NOT documented: regional vs global, and
whether delete propagates across regions. So we cannot assume global
invalidation.

Design that is correct either way:
- Warm read: `cache.match(canonical_url)` -> hit serves the full Response with
  ZERO kv ops. Miss -> resolve via index get -> render machine -> `cache.put`
  with `Cache-Control: public, max-age=<TTL>` -> serve.
- Invalidate on write (primary): on every mutation, `cache.delete()` the exact
  canonical URLs the page answers (see matrix). Instant in at least the writing
  region; global if the cache is global.
- TTL ceiling (safety net): `max-age=<TTL>` bounds staleness to TTL in any region
  a delete did not reach. Pick conservative (~60s) until we EMPIRICALLY verify
  propagation on Deploy; raise it (toward indefinite) if delete proves global.
  This is the honest "any sacrifice for the link": fastest possible warm serve,
  bounded-and-rare staleness on edits.

URLs a page answers (delete + cache keys), each also with `.pdf` variant:
- default: `/{display_username}` (named user) or `/id/{user_id}` (anon)
- named:   `/{display_username}/{display_name}`
Mutations -> delete: content edit, css edit, pdf set/remove, toggle default
(old+new default page), rename name, nik rename (ALL user's pages — cascade),
delete page. Cache is keyed by the CANONICAL (display-cased) URL.

render_version stays useful for ETag/conditional revalidation but is NOT needed
in the cache key (URL-keyed + delete + TTL covers correctness).

## 2. Case-preserving username/name: indexed (lc) + display (raw)

Store BOTH per identity segment:
- indexed, lowercased: `username` (the nik, lc) and `name` (lc) -> these back the
  kvdex primary indices (`default_at_username`, `[username, name]`). Uniqueness +
  reserved checks run on the lc form.
- display, raw-case, NOT indexed/searched: `display_username`, `display_name` ->
  what we render and redirect to. Denormalized onto the page (avoids an extra get
  on the link path); cascaded on nik rename like the lc form.

Insert: lowercase -> check (unique + reserved) on lc -> save raw as display + lc
as indexed.

Get (public resolve of `/{seg1}` or `/{seg1}/{seg2}`):
1. lower the segment(s), look up by the lc index.
2. on hit, if the incoming segment(s) != the stored display value(s) ->
   REDIRECT to the canonical display URL (clients treat the link as the canonical
   representation). Use 302/307 (NOT 301) so a later display-case change isn't
   stuck in browser caches.
3. if already canonical -> serve content (L3 cache / render).

Interaction with L3: only the canonical URL caches content; a non-canonical hit
needs the index get to discover the display casing, then redirects (optionally
cache the redirect with a short TTL). Shared links are canonical, so the hot path
stays zero-kv.
