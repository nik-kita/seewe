# Removed the legacy mdcv backend; production is page-only

Executed [[027.decision]].

Deleted: `api/routers/mdcv/` (9 files), `api/services/md-cv_service.ts`,
`api/spa_subserver/spa_subserver.tsx`. Moved `dto/md-cv.dto.ts` ->
`dev/legacy_md-cv.dto.ts` (header marks it migration-only).

Edited:
- `v1.ts`: dropped the `/mdcv` route + import.
- `db.ts`: removed `_dev_md_cv` + `_dev_md_cv_pdf` collections and the MdCv
  relaxed wrapper/import; refreshed the `nik` index comment.
- `services/users_service.ts`: `add_nik` now calls
  `page_service.cascade_user_rename(user, nik)` instead of writing the dead
  `_dev_md_cv` — a real fix (a user claiming a nik post-cutover would otherwise
  have no `default_by_username`, so `/:username` would 404).

  collections) so it no longer depends on `db.ts` for the old shape; reads cvs/pdfs
  via `legacy`, writes pages/users via `make_db`. Also fixed `newest_dump()` to
  only pick `kv-dump.*` files (it had grabbed its own newer `kv-fixture.*` output
  and produced a 0-cv no-op).
- `dev/schema_snapshot.ts`: SCHEMA_SOURCES + manifest now name `_dev_page*`.

transform end-to-end -> 26 pages / 2 pdfs / 6 nik_lc / 187-entry fixture (unchanged
from before the refactor). Left in place deliberately: raw `nik` index +
uncalled `find_by_nik` (user identity, not mdcv).
