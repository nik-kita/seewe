# Keep kvdex (supersedes 006); simplify the schema instead

Reverses [[006.decision]]: the new `page` version KEEPS kvdex. kvdex is not the
problem to solve. Zod stays (it already backs kvdex collections).

The simplification the user wants is at the **data-model** level, not the
storage-engine level: make collections, indices, and the record shape explicit
and specific to the actual queries — drop the CV-era cruft, not the library.

So the paused [[kv-restore-migrate]] transform stays a kvdex-layout ->
kvdex-layout mapping (as originally framed), not a cross-engine rewrite — the
forward note added in its 003.log no longer applies.

Next: design the simplified kvdex schema for `page` + `user` from the query
inventory (see [[006.decision]]'s inventory section, which is still valid).
