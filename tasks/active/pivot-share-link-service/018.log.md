# Slice 4c (machine part): render machine -> page-serving machine

Per user: rebuild 4a's render machine into the full page-serving machine, keeping
the deep not-found nuances in the handler (a single `fallback` decision).

`git mv` render_machine.{ts,test.ts} -> serving_machine.{ts,test.ts}; rewrote both.

`serving_machine` states: `resolve` (invoke lookup actor) -> `canonicalize`
(entry computes the canonical display redirect) -> `redirect` | `serve_artifact`
(invoke load_pdf) -> `artifact_ready` | `render_md`; unresolved/`onError` ->
`fallback`. Output union: `fallback | redirect{to} | artifact{page,pdf} |
site{page}`.

Design held:
- machine owns the DECISIONS (resolve, canonical display/lowercase compare,
  render); IO (lc-index lookup, pdf load) injected via input -> pure/testable.
- canonicalization is generic via injected `display_of(page)` + raw `incoming`
  segments; the lc-for-lookup lives in the route's `resolve` closure. The /id
  route reuses it: `incoming=[]`, `display_of` yields `[username]` if any -> a
  named user's /id redirects to /username; a nik-less default renders.
- redirect short-circuits BEFORE serve_artifact, so a non-canonical pdf hit
  never reads the blob just to discard it (tested).

14 tests pass (`deno task test`): fallback (null + error), canonical redirect
(username, name, /id), already-canonical render, artifact/site/degrade, no-blob-
read on md + on redirect, white-box final states. `deno check` clean.

Remaining in slice 4: the HANDLER (`page_subserver`) that builds `ServeInput`
per route + turns `ServeDecision` into a Response (incl. serve_static fallback,
the not-found nuances, `.pdf` suffix) and 4d CDN cache headers; plus 4b user nik
lc/display split (needed by the handler's username resolve + uniqueness).
