# Slice 3 done: page_service

Added `api/services/page_service.ts` (port of md-cv_service to `_dev_page` with
the lc-index + raw-display model). Surface: `save`, `save_as_default`, `update`,
`toggle_default`, `set_pdf`, `get_pdf`, `remove_pdf`.

Key logic:
- identity derived in the service, never from caller input: raw `display_username`
  / `display_name` set alongside the lowercased routing keys (`default_by_username`,
  `by_username_and_name=[lc_user, lc_name]`).
- `display_*` is left in place when a key is cleared (dead data, only read after a
  routing index matches) — keeps un-default simple and correct for dual-addressed
  pages.
- a named user's default page carries BOTH `default_by_user_id` (so `/id/:uid`
  resolves) and `default_by_username` (so `/:username` resolves); a nik-less user
  gets only `default_by_user_id`.
- `name` uniqueness per user is enforced by the compound primary index (add fails
  on a taken `[username, name]`).

Verified with a local smoke test (12/12, then cleaned up): /:username, /:username
/:name and /id/:user_id all resolve via the lc indices; display values raw-cased;
duplicate name rejected; toggle moves the default and clears the old; nemo path
has no username fields; pdf set/get/remove round-trips. `deno check` clean.

Deferred to later slices: the nik-rename cascade over `_dev_page`
(`display_username`/`default_by_username`/`by_username_and_name`) — currently
still in users_service against `_dev_md_cv`; rewire at cutover.
