# New noun: `page`

The generic unit the rebrand renames `mdcv` to is **page** (matches the
product framing "share a page via a link"). A page has a representation
(markdown-rendered or an uploaded artifact); a CV is just a page.

## Concrete API naming (rename target)

| old (CV-shaped)            | new (page)                  |
| -------------------------- | --------------------------- |
| collection `_dev_md_cv`    | `_dev_page`                 |
| blob coll. `_dev_md_cv_pdf`| `_dev_page_pdf` (key `page_id`) |
| route `/v1/mdcv`           | `/v1/page`                  |
| dir `api/routers/mdcv/`    | `api/routers/page/`         |
| `MdCvDto` / `MdCvEntityDto`| `PageDto` / `PageEntityDto` |
| `MdCvPdfDto`               | `PagePdfDto`                |
| `dto/md-cv.dto.ts`         | `dto/page.dto.ts`           |
| `services/md-cv_service.ts`| `services/page_service.ts`  |
| `mdCv_service`             | `page_service`              |

Keep the `_dev_` prefix convention. Public serving (`/:slug`, `/:username`,
`.pdf`) and the publish/default slug fields carry over unchanged — they were
never CV-specific.

## Still open (next sub-decision, not blocking the rename)

- Content-type model: today `kind: "md" | "pdf"`. The pivot wants this open to
  more types without a new endpoint per type — decide whether to keep the
  closed enum for now or generalize (e.g. `kind: string` + a representation
  sub-shape). Can be deferred; the rename does not depend on it.

## Effect

Unblocks the rename and gives [[kv-restore-migrate]]'s `transform_entry` its
target: old `_dev_md_cv` record → `_dev_page` record (field-for-field for now,
since schema is preserved). Parent moves blocked -> active.
