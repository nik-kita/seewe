# Link cache: use Deno Deploy CDN + cache tags (global purge), not the Web Cache API

Verified via Deno docs (couldn't deploy a probe from here, but the docs are
explicit). Two distinct caches exist on Deploy:
- Web Cache API (`caches.open`) — REGIONAL, not global. Wrong tool; would need a
  TTL ceiling for cross-region staleness.
- CDN/HTTP layer — GLOBAL. `Cache invalidation is automatically synchronized
  across all Deno Deploy regions`; tag purge `propagates globally within seconds`.

So L3 becomes CDN-based and gets the "infinite" property safely:

- Serve public page responses with `Deno-CDN-Cache-Control: public, s-maxage=<N>`
  (highest-priority header; falls back to `CDN-Cache-Control` / `Cache-Control`).
  N can be very long because purge is global+fast.
- Tag each response with `Deno-Cache-Tag` for precise purge WITHOUT enumerating
  URLs:
  - `page-<id>` — purge one page (content/css/pdf/default edits).
  - `user-<id>` — purge ALL a user's pages in one call (nik rename cascade becomes
    a single purge, not per-URL).
- Invalidate on write: `POST http://cache.localhost/invalidate/http` with
  `{ "tags": [...] }`. Internal endpoint, Deploy-only.

This supersedes [[010.decision]]'s regional Web-Cache design (URL-keyed delete +
TTL ceiling). The existing pdf Web-Cache (`caches.open("seewe-pdf-v1")` in
spa_subserver) migrates to the same CDN-tag scheme for consistency + global
behavior.

## TTL config (per user request)

`s-maxage` comes from env (e.g. `CACHE_S_MAXAGE`) with a sensible default, so it's
tunable. Since global purge is proven, the DEFAULT can be long (effectively
"cache until purged"); env still overrides. render_version is no longer needed
for cache correctness (tags handle it); keep it only if useful for ETag.

## Prerequisite to confirm

These headers/endpoint are CURRENT Deno Deploy features. Confirm seewe.deno.dev
runs on current Deploy (not Classic). If Classic, only the regional Web Cache +
edge cache are available and we fall back to [[010.decision]].
