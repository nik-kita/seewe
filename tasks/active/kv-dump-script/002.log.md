# Dump script implemented + validated locally

Added `api/dev/kv_dump.ts`. Decisions made while writing it:

- **Connect**: env-driven. `KV_CONNECT_URL` (remote Deno Deploy connect url) +
  `DENO_KV_ACCESS_TOKEN` (read automatically by `Deno.openKv`). No secrets or DB
  id hardcoded; omit `KV_CONNECT_URL` to dump the local kv. Errors out early if
  a connect url is set without a token.
- **Format**: v8 binary via `node:v8` `serialize` (lossless for KV value types
  incl. `Uint8Array`). Buffer re-wrapped as a plain `Uint8Array` for
  `Deno.writeFile` (type fix).
- **Raw-level dump confirmed correct**: `kv.list({ prefix: [] })` returns
  everything under kvdex's `__kvdex__` namespace — sample key
  `["__kvdex__","_dev_md_cv","__id__", ...]`. So index entries and the chunked
  `_dev_md_cv_pdf` blob parts are captured verbatim, exactly as intended.
- Output: timestamped `api/dev/kv-dumps/kv-dump.<target>.<stamp>.v8`; dir
  gitignored (`api/.gitignore`), since dumps hold real user data. Per-prefix
  counts printed.

Validation: `deno check` clean; local dry run dumped 26 entries; round-trip
`deserialize` returned all 26 with keys intact. Test dump deleted.

Remaining (user step): run against the real remote KV with `KV_CONNECT_URL` +
`DENO_KV_ACCESS_TOKEN`. Script side is complete.
