# Restore script implemented (verbatim) + validated

Per the user's call: preserve the current schema for now, build a verbatim
restore, and defer the old->new transform to "the moment of restore". Added
`api/dev/kv_restore.ts`.

Design:
- Reads a v8 dump (positional arg, or newest in `dev/kv-dumps/`), `deserialize`s
  to `{key,value,versionstamp}[]`, and `kv.set(key, value)` each entry — raw,
  so kvdex records + indices + chunked `_dev_md_cv_pdf` blob parts rebuild
  exactly. versionstamp is ignored (can't be set on write).
- **Transform seam**: `transform_entry(entry) => entry | null`, identity today.
  This is where the old(CV)->new(page) schema mapping will plug in later, once
  the new schema noun/shape is decided in [[pivot-share-link-service]].
- Target is env-driven: `KV_RESTORE_TARGET` (remote connect url | local sqlite
  path | omit = default local kv), `DENO_KV_ACCESS_TOKEN` for remote.
- **Safety guard**: refuses a non-empty target unless `RESTORE_FORCE=1`, so a
  restore can't silently merge onto live data.

Validation (local, end-to-end): dump 26 -> restore into fresh temp kv -> 26
written; target re-read shows 26 entries (`_dev_md_cv` 18, `_dev_users` 8),
matching source; non-empty-target guard correctly refused on re-run. `deno
check` clean. Test artifacts removed.

Status: verbatim restore is done. The migration (transform) half is intentionally
deferred and blocked on the new schema from [[pivot-share-link-service]].
