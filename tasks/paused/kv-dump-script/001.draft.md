# KV dump script (backup before rebrand)

## Goal

A repeatable script that connects to the live Deno KV and writes every entry to
a local, gitignored dump file. It is the prerequisite for the share-link rebrand
([[pivot-share-link-service]]) and the input for [[kv-restore-migrate]].

## What must be captured

Current collections (api/db.ts): `_dev_users`, `_dev_md_cv`, `_dev_md_cv_pdf`.
kvdex stores each collection plus its index entries under KV key prefixes, and
`_dev_md_cv_pdf` is `serialize:"v8"` + chunked. To guarantee a faithful restore,
dump at the **raw KV level** (`kv.list({ prefix: [] })`), not through kvdex — so
index keys and chunked blob parts are all captured exactly as stored.

## Connection

- Remote: `Deno.openKv("https://api.deno.com/databases/<DB_ID>/connect")` with
  `DENO_KV_ACCESS_TOKEN` set from the user's `ACCESS_TOKEN`.
- Local fallback: `Deno.openKv()` for dev/testing the script itself.
- DB id / connect URL: TBD from the user.

## Format

Each entry is `{ key: Deno.KvKey, value: unknown, versionstamp }`. Values
include `Uint8Array` (blob chunks). Options:
- v8 serialize the whole array to a binary file (lossless, Deno-native), or
- JSON with `Uint8Array` → base64 (inspectable, portable).
Lean v8 for fidelity unless inspectability is wanted.

## Steps

1. Confirm connect URL + that `ACCESS_TOKEN` is the `DENO_KV_ACCESS_TOKEN`.
2. Write `api/dev/kv_dump.ts` (or scripts/): connect, `list` all, serialize,
   write timestamped file, log per-prefix counts.
3. Dry run against local KV, then a real dump.
4. Gitignore the dump output.

## Open questions
